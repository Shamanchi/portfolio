# Как устроен рой CodexHub

CodexHub — собственная разработка автора: настольное приложение на Electron,
React и TypeScript, которое управляет профилями Codex CLI, запускает
изолированные сессии с разными ключами и оптимизирует кэш LLM через локальный
прокси. Одна из его возможностей — режим роя.

## Состав роя

- Оркестратор: ставит задачи, распределяет по исполнителям, собирает отчёты,
  ведёт доску.
- Исполнители: до 7 агентов, каждый делает одну задачу.
- Аудитор: другой агент, не исполнитель; читает diff, сам запускает проверки
  и выносит вердикт APPROVE или REJECT.

## Цикл задачи

1. Задача на доске: описание, предложение, риски, приоритет.
2. Исполнитель работает в изолированной папке задачи.
3. Приёмка: quality gate и тесты зелёные, инструкция из README проверена.
4. Аудит чужим агентом: diff, собственный прогон проверки, обоснованный
   вердикт.
5. Одобрение пользователя. Без него задача не закрывается.
6. Коммит в ветку задачи, при необходимости pull request. Рабочие ветки
   удаляются только после одобрения.

## Правила, которые держит рой

- Каждая задача закрывается отдельно: README, тесты, шаг в CI, аудит.
- Новый батч не начинается, пока предыдущий не принят.
- При упоре в лимит расхода или времени — остановка и честный доклад о том,
  что осталось. Качество не срезается.
- Чужой код не копируется: источники тем указаны в NOTICE.md, реализации
  собственные.

## Связь с этим портфолио

Портфолио собрано рой-сессией по этому циклу: каждая волна и каждый проект
прошли стадии «задача — работа — гейт — аудит — одобрение». Отчёты и доски
рабочих прогонов хранятся в .swarm/ и не публикуются.
