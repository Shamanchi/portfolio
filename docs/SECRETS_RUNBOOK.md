# Runbook: ключи и секреты

## Правила

- Ключи читаются только из переменных окружения. Никаких ключей в коде,
  README и коммитах.
- Файл .env никогда не коммитится. В репозитории лежит .env.example с пустыми
  значениями и списком ожидаемых переменных.
- CI работает без ключей. Сетевые шаги помечаются необязательными и не
  ломают сборку, если переменной нет.
- Внутренние пути машины (абсолютные пути под профилем пользователя) в
  коммиты не попадают.

## Как проверить

1. npm run secrets — сканирование всего дерева на ключи, токены, приватные
   ключи и файлы .env.
2. Проверка считается пройденной, когда вывод заканчивается строкой
   secrets scan: ok.

## Что делает сканер

- Все файлы репозитория, кроме node_modules, .git, .swarm, dist, build,
  coverage и бинарных файлов.
- Паттерны: приватные ключи, ключи AWS, токены GitHub, ключи в стиле OpenAI,
  токены Slack и Stripe, ключи Google.
- Файл .env в любом месте дерева — ошибка.
- Тексты, содержащие абсолютные пути под профилем пользователя, — ошибка.

## Что делать при находке

1. Определить файл и строку из вывода сканера.
2. Если в коммитах уже есть секрет — считать его скомпрометированным:
   отозвать и выпустить новый ключ, не «подчищать историю» поверх.
3. Убрать источник секрета (переменную окружения, точечный файл).
4. Перепроверить: npm run secrets.
5. При необходимости записать вывод в .swarm/ как отчёт — вне коммита.

## Как включить сетевой шаг по желанию

Проект работает без сетевых шагов по умолчанию. Для реального прогона
задайте переменные из .env.example в окружении (например, через файл .env) и
запустите команду проекта, которая помечена как Optional. Без переменной
такая команда либо пропускается, либо падает с осмысленным сообщением, но
базовый сценарий и CI остаются зелёными.
